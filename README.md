# 📸 snap-budget

> **사용내역 캡쳐 한 장으로 입력하는 가계부.**
> 카드·페이 거래내역 스크린샷을 올리면 브라우저에서 글자를 읽어(OCR) 여러 건을 한 번에 자동 입력합니다.

기존에 손으로 일일이 타이핑하던 가계부를, **"캡쳐 → 자동 입력"** 으로 바꾼 개인 프로젝트입니다.
API 키·서버·결제 없이 **전부 무료**로 동작합니다.

---

## ✨ 주요 기능

| 기능 | 설명 |
|------|------|
| 📷 **캡쳐 OCR 자동입력** | 거래내역 스크린샷 → 글자 인식 → 가맹점·금액·날짜를 자동 추출, 여러 건 일괄 등록. 은행 계좌(잔액 줄)·카드 이용내역(할부·승인취소)·페이 앱 화면, 날짜 헤더는 "10월 17일 토요일"·"10월 17일 (토)"·"10.17 (토)"·"2026.10.17"·"오늘"·"어제" 모두 인식 (다크모드·저해상도·JPEG 캡쳐도) |
| 📚 **여러 장 한 번에** | 스크롤하며 찍은 캡쳐 여러 장을 한꺼번에 올려 차례로 인식. 장 사이에 겹쳐 찍힌 거래는 한 번만 넣고, 위가 잘려 날짜 헤더가 없는 장은 앞 장의 날짜를 이어받음 (고른 순서와 상관없이 날짜·겹치는 거래로 화면 순서를 맞춤). 아주 긴 스크롤 캡쳐는 글자 줄 사이 빈 곳에서 조각으로 나눠, 줄이지 않고 읽음 |
| ✍️ **빠진 내역 직접 추가** | 사진에서 못 읽은 거래는 확인 목록에서 바로 추가해 인식한 내역과 함께 저장. 날짜도 목록에서 바로 고칠 수 있고, 사진을 더하거나 빼도(실수로 뺀 사진을 다시 넣어도) 고친 내용·지운 줄은 유지. 인터넷이 끊겨 글자 인식 엔진을 못 불러와도 화면이 멈추지 않고 직접 추가는 가능 |
| 🏷️ **자동 카테고리 분류** | 가맹점명 기반 규칙으로 외식비·생필품·교통비 등 자동 분류 (수정 가능). 여러 키워드가 걸리면 더 구체적인(긴) 것이 이기고("쿠팡이츠"는 외식비, "방탈출카페"는 취미), "CU"·"KT" 같은 짧은 약어는 단어로 떨어져 있을 때만 인식 |
| 🧠 **학습형 분류** | 사용자가 카테고리를 고치면 그 가맹점을 기억해, 다음 캡쳐부터 자동 적용 (쓸수록 정확해짐) |
| 🚫 **수입 자동 제외** | 입금·이자 등 `+` 거래는 지출 통계에서 자동 제외 |
| ♻️ **중복 거래 방지** | 같은 캡쳐를 다시 올려도 이미 저장된 거래(같은 날·시간·금액, 시간을 모르면 가맹점까지 — 띄어쓰기·대소문자 무시)는 자동으로 건너뜀. 저장 후 이름을 고쳤어도 알아보고, 같은 분에 같은 금액 두 건(커피 두 잔)은 둘 다 저장. 직접 추가한 줄은 거르지 않음 |
| 🗓️ **월별 관리** | 월 탭으로 월마다 따로 관리, 캡쳐 항목은 날짜에 맞는 월로 자동 분류 저장 (1월에 12월 말 내역을 올려도 작년 12월로, 결제 예정 같은 가까운 미래 날짜는 올해로). 다른 달에만 들어갔으면 그 달을 보여 주고, '추가' 탭으로 돌아오면 원래 보던 달로. 직접 추가할 때 다른 달 날짜를 고르면 그 달에 저장 |
| 🎯 **예산 + 잔여 예산 바** | 월 예산 설정, 사용률(%)·초과 경고 색상 표시 |
| 📊 **차트** | 카테고리별 지출 도넛 차트 + 막대 상세 |
| 📅 **달력 뷰** | 일별 소비 금액을 달력에서 한눈에 |
| ✏️ **수정/삭제** | 내역 탭해서 카테고리·내용·금액·날짜 수정 (다른 달 날짜로 고치면 그 달로 옮김, 다른 기기에서 이미 지운 내역이면 알려줌) |
| 📋 **내역·검색** | 날짜·시각 최신순 목록, 내용·카테고리 검색(대소문자 무시) |
| 👨‍👩‍👧 **가족 코드 공유** | 추측 불가능한 가족 코드(hid)로 데이터를 나눠 담고, 🔗 초대 링크를 받은 가족끼리만 같은 가계부를 공유 |
| ☁️ **클라우드 동기화** | 접속하면 익명 자동 로그인 → 같은 가족 코드를 쓰는 폰·PC 어디서나 같은 데이터. 두 사람이 동시에 편집해도 유실 없이 안전(원자적 저장) |
| 📱 **PWA** | 홈 화면에 앱처럼 설치 + 기본 오프라인 |

## 🛠️ 기술 스택

- **Frontend**: 순수 HTML / CSS / JavaScript (ES Modules, 빌드 도구 없음)
- **OCR**: [Tesseract.js](https://tesseract.projectnaptha.com/) — 브라우저 안에서 도는 무료 한글 OCR
- **차트**: Chart.js
- **백엔드/DB**: Firebase Authentication + Cloud Firestore
- **배포**: GitHub Pages
- **PWA**: Web App Manifest + Service Worker

> 별도 서버가 없는 **순수 클라이언트 앱**입니다.

## 🧩 동작 흐름

```
캡쳐 업로드 (여러 장 가능)
   │  Tesseract.js (브라우저 OCR, 장마다 차례로)
   ▼
장별 원문 텍스트
   │  parse.js     ── "부호+금액+원" 패턴으로 거래 추출, 수입(+) 제외, 날짜/시간 매칭
   │  capmerge.js  ── 여러 장을 화면 순서로 잇고(잘린 날짜 이어받기), 겹쳐 찍힌 거래는 한 번만
   ▼
[{가맹점, 금액, 날짜}]
   │  categorize.js ── 가맹점명 → 카테고리
   ▼
확인·수정 목록
   │  날짜가 속한 '월'로 그룹핑
   ▼
Firestore  households/{hid}/budgets/{년_월}  ──▶  차트·달력·예산에 반영
```

## 🚀 직접 만들어 쓰려면

1. 이 저장소를 클론
2. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성
   - **Authentication → 로그인 방법 → 익명(Anonymous)** 사용 설정
   - **Firestore Database** 생성 후 `firestore.rules`의 규칙을 붙여넣고 게시
3. `src/firebase-config.js`의 값을 본인 Firebase 웹앱 설정으로 교체
4. 정적 서버로 실행 (ES Module은 `file://`에서 막힘):
   ```bash
   npx serve -p 3000     # 또는: python -m http.server 3000
   ```
5. 브라우저에서 `http://localhost:3000` → 접속하면 익명 로그인되어 바로 사용
6. 가족과 공유하려면 헤더의 🔗 버튼으로 **초대 링크(`?h=가족코드`)를 복사**해 전달 → 링크를 연 가족은 같은 가족 코드를 채택해 같은 가계부를 공유

> 🔒 `firebaseConfig`의 apiKey는 비밀이 아니라 공개 식별자입니다. 보안은 Firestore 규칙(로그인된 요청만 허용)이 담당합니다.
> 데이터는 `households/{가족코드}` 아래로 나눠 담기며, **추측 불가능한 가족 코드(hid)를 아는 가족끼리만** 같은 가계부를 봅니다(링크 공유형 모델). 코드를 모르는 외부인은 접근할 수 없습니다.

### GitHub Pages 배포 시
- Firebase **Authentication → 설정 → 승인된 도메인**에 `<username>.github.io` 추가

## 💡 만들면서 배운 것

- 브라우저 OCR(Tesseract.js)로 한글 거래내역을 인식하고, **정규식으로 노이즈를 걸러 구조화**하는 과정
- OCR은 완벽하지 않으므로 **"사람이 확인·수정하는 관문"** 을 둬 데이터 품질을 확보
- **익명 로그인 + Firestore 규칙**으로, 별도 가입 없이도 "로그인된 요청만 허용"해 데이터를 보호
- apiKey는 비밀이 아니라는 점, 보안은 클라이언트 키가 아니라 **서버 규칙**에서 온다는 점
- 전역 공용에서 **`households/{가족코드}` 격리 + 링크 공유형 모델**로 옮겨, 코드를 아는 가족끼리만 공유하도록 좁힌 과정
- 문서 전체를 덮어쓰던 저장을 **용도별 원자적 연산**(추가=arrayUnion / 예산=merge / 수정·삭제=트랜잭션)으로 바꿔, 두 사람이 동시에 편집해도 유실이 없게 만든 것
- 캡쳐 여러 장을 합칠 때, 고른 순서를 믿지 않고 **날짜 헤더·겹쳐 찍힌 거래로 화면 순서를 복원**해 잘린 날짜를 이어받고 이중 집계를 막은 것
- 저장소를 가짜 모듈로 바꿔치기한 **실제 브라우저 E2E**로, 빈 공간이 대부분인 캡쳐에서 대비 보정이 그림을 통째로 검게 만들던 버그(하위 1% 밝기가 곧 배경색)를 찾아 고친 것
- '같은 거래인가' 규칙을 캡쳐 합치기와 저장 중복 거르기가 **한 함수로 함께 쓰게** 정리해, 두 곳이 서로 다른 답을 내던 문제(자정 결제·띄어쓰기 다른 가맹점명)를 없앤 것
- 은행·카드·페이 앱 모양의 가짜 캡쳐를 여러 스타일(다크모드·저해상도·큰 글씨·JPEG 압축·스크롤 여러 장)로 만들어 **정답과 자동 채점**하고, 틀린 건마다 OCR 원문을 보며 원인(헤더 형식, '원'의 오독, 잔액 오독으로 엉뚱해진 잔액 산수 등)을 고쳐 정확도를 61/83 → 104/104로 올린 것
- 저장소에 달마다 응답 지연·실패를 줄 수 있는 가짜 모듈로 **비동기 경쟁 상태**를 재현해(9월을 눌렀다 바로 10월로 가면 늦게 온 9월 응답이 10월 화면을 덮음), 요청 번호로 늦은 응답을 버리고 화면에 보이는 달을 따로 기억하게 고친 것
- 라이브러리가 실패를 promise로 알려주지 않는 경우(Tesseract.js는 언어 데이터를 못 받으면 영원히 대기)를 소스에서 확인하고, 오류 콜백 + 시간 제한으로 멈춤을 막은 것
